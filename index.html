  • 게이트웨이 계층의 인터페이스 설계Interface design at the gateway 증권사마다 인증과 전문 헤더 규격이 달라 같은 처리가 여러 서비스에 흩어져 있던 구조를, Spring Cloud Gateway 계층에서 헤더 변환과 공통 처리를 흡수하도록 설계했습니다. 연동 증권사가 늘어도 서비스 코드를 고치지 않고 게이트웨이 설정으로 대응합니다. Analysed each firm's account-opening, balance, order and execution specs, defined a common data spec, and mapped divergent responses into one shape for the service.   • 조회 성능 개선 (N+1 → MyBatis)Query performance (N+1 → MyBatis) 고객·포트폴리오·계좌·구성종목·기준가·평가금액을 함께 조회하는 구간에서 연관 엔티티 반복 조회(N+1)가 발생해, 복잡한 조회 구간을 MyBatis로 분리했습니다. 기본 CRUD는 JPA로, 복잡한 조회는 MyBatis로 도구를 목적에 맞게 나눈 선택이었고, 부하 테스트로 병목 지점을 특정한 뒤 개선했습니다. Fetching customer, portfolio, account, holdings, NAV and valuation together triggered N+1 queries on lazily loaded associations, so I moved that read path to MyBatis — keeping JPA for straightforward CRUD and using MyBatis where queries get complex — after load testing to pinpoint the bottleneck.

Designed the flow so that buy and rebalancing orders derived from the robo-advisor's allocation were transmitted exactly and executions reflected back, verified data consistency in Oracle, and kept the integration batches running.
